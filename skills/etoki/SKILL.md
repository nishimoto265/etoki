# etoki — 図と音声で仕組みを説明するページを作る

あなたが書くのはデータファイル（YAML）1 つだけ。図の配置、線の通り道、再生画面、読み上げの音声、崩れの検査は道具がやる。

道具の場所（以下 `ETOKI`）: このスキルのフォルダの 2 つ上にある `bin/etoki.js`。スキルのフォルダがシンボリックリンクなら、実体（`realpath`）から数える。見つからなければ `etoki` コマンドを使う。Node 20 以上で動く。

```
node ETOKI build <データファイル.yaml> --shots 0,3,7
```

初めて動かすと、部品（約 330 MB）、読み上げのモデル（約 330 MB）、検査用のブラウザを `~/.cache/etoki` などに入れる。数分かかることをユーザーに一言伝える。

## 手順

1. **題材を 1 つに決める。** 何の仕組みを、どの具体例で見せるか。値は実際のものか、「（例）」と書いた例の値を使う
2. **データファイルを書く**（形は下）。置き場所はユーザーの指定どおり。指定が無ければ作業中のフォルダに `<題材>/etoki.yaml`
3. **組み立てる**: `node ETOKI build <file> --shots 0,<途中>,<最後>`
4. **誤りと崩れを直す。** 出力に「データファイルの誤り」「崩れ N 件」「読みに英字が残っています」が出たら、データファイルを直して 3 に戻る。崩れ 0 件になるまで繰り返す。「崩れの検査をしていません」と出たら、検査用のブラウザが起動できていない（サンドボックスの中など）。サンドボックスの外で動かす許可をもらって組み立て直し、許可がもらえなければ検査できていないことをユーザーに伝える
5. **画面を自分で見る。** `--shots` で撮った PNG を読み、文字が小さすぎないか、付箋が読めるかを確かめる
6. **ユーザーに渡す。** できた HTML を開いて見せる。見せたいステップと、使った声を一言添える

## データファイルの形

```yaml
title: 商品一覧が表示されるまで
voice: kokoro:jf_alpha          # 省略可。下の「声」を参照
readings:                       # 省略可。読み方の足し
  example.com: イグザンプル ドット コム

figure:
  columns:                      # 左から右へ並ぶ列。図の大きな区切り
    client: 端末
    edge: 入口
    data: データ
  nodes:                        # 箱。col（列）と row（上から何段目、0 始まり）だけ書く
    br:  { col: client, row: 1, label: ブラウザ, sub: 商品一覧, icon: browser }
    dns: { col: edge, row: 0, label: DNS, sub: 名前 → IP, icon: book }
    db:  { col: data, row: 1, label: データベース, kind: store, icon: db }
  edges:                        # 線。「a -> b」
    - br -> dns
    - br -> db

steps:
  - title: 全体を見る           # 最初のステップは必ず全体
    says:
      - text: ページは、左の端末から右のデータまで、3 つの段を通って表示される。
  - title: 名前を引く
    says:
      - text: ブラウザは、まず DNS にドメインの IP アドレスを聞く。
        flow:                   # この文で光らせる線。線の端の箱も光る
          - br -> dns: shop.example.com は？    # 「線: 札」で線の上に札を出す
      - text: DNS は、IP アドレスを返す。
        flow:
          - dns -> br: 203.0.113.10             # 逆向きに書けば矢印も逆になる
        notes:                  # 箱のそばに貼る付箋
          dns: 例の値
```

### 箱（nodes）に書けるもの

| 項目 | 意味 |
|---|---|
| `col`, `row` | 列と段。座標は書かない |
| `label`, `sub` | 名前と、その下の小さな説明 |
| `icon` | 絵。道具の絵（browser book cloud split server db db2 cache folder person phone queue gear log chart lock key mail gateway file video code globe robot）、`lucide:名前`（lucide のアイコン）、`icons/` に置いた SVG のファイル名 |
| `kind` | `store`（置き場。角が丸く色が付く）、`ext`（外のサービス。枠が点線） |
| `span` | 縦に何段ぶん使うか |
| `in` | 親の箱の id。箱の中に小さな箱を並べるときに使う（`col`, `row` は親の中での位置） |
| `w`, `h`, `x`, `y` | 大きさと位置を自分で決めたいときだけ |

線に `d:` を書くと通り道を自分で決められる（`- { edge: a -> b, d: "M0 0 L10 10" }`）。崩れが直らないときの最後の手段。

### 文（says）に書けるもの

| 項目 | 意味 |
|---|---|
| `text` | 画面に出て、読み上げる文。1 文だけ |
| `flow` | 光らせる線。`a -> b` か `a -> b: 札` |
| `notes` | 箱のそばの付箋。`箱: 文字` |
| `on` | 線を通らずに光らせたい箱 |
| `zoom` | 拡大する箱。**箱の中に小さな箱があるときだけ使う**。中身の無い箱を拡大しない |
| `caption` | 画面に出す文を読み上げと変えたいとき |
| `say` | 読み上げだけ変えたいとき |

## 書き方の決まり

- 最初のステップは「全体を見る」。図全体を見せ、どこに何があるかを言う
- 1 つの文は 1 文。「。」は 1 つまで
- 具体的な値を札と付箋に出す（`GET /api/items?page=1`、`CPU 20%` など）。札は「線を通るもの」、付箋は「箱の今の状態」
- 1 つの図の箱は 15 個くらいまで。それ以上なら説明を 2 本に分ける
- 比喩を使わない。実際の名前と値で言う
- 英字は、大文字の略語（DNS、API）なら道具が 1 文字ずつ読む。それ以外の英字（`Redis`、`fooBar`）は読み方の辞書か `readings:`、`say:` で読み方を書く。書かないと組み立てが止まる

## 声

声はユーザーとの会話で決める。ユーザーにコマンドを打たせない。

| ユーザーが言うこと | すること |
|---|---|
| 何も言わない | いつもの声で作る（設定ファイル、無ければ `kokoro:jf_alpha`） |
| 「男性の声で」など | データファイルに `voice: kokoro:jm_kumo` を書く |
| 「これからずっとこの声で」 | `~/.config/etoki/config.yaml` に `voice: <声>` を書く |
| 「どんな声があるの？」 | `node ETOKI voices --out <場所>/voices.html` で聞き比べのページを作って開く |
| 「音声なしで」 | `voice: none`。見る人のブラウザに読ませるなら `voice: browser` |

声の一覧: `kokoro:jf_alpha`（女性）、`kokoro:jf_gongitsune`（女性）、`kokoro:jf_nezumi`（女性）、`kokoro:jf_tebukuro`（女性）、`kokoro:jm_kumo`（男性）。

## そのほか

- 動画（mp4）も欲しいと言われたら `--video` を付ける（ffmpeg が要る）
- 作った音声は文ごとに `~/.cache/etoki/audio` に残る。直した文だけ作り直すので、2 回目からは速い
- 遅いパソコンで読み上げが重すぎるときは、`voice: browser` に切り替えられることを伝える
